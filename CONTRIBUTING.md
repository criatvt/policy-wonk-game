# Contributing

Policy Wonk is open source under CC BY-NC 4.0. This doc explains the development workflow so future-you (or new contributors) don't have to reverse-engineer it.

## Source of truth

- **Open work** lives in [GitHub Issues](https://github.com/criatvt/policy-wonk-game/issues).
- **Phasing** lives in [`ROADMAP.md`](./ROADMAP.md). To see the current phase's issues:
  ```sh
  gh issue list -l phase-1
  ```
- **Non-negotiable rules** (design guardrails, the release checklist, gotchas) live in [`CLAUDE.md`](./CLAUDE.md) at the repo root. Claude Code loads it automatically at the start of every session; read it first if you're working here by hand.

## Branching model

Two long-running branches, as of 2026-08-24 (replaces the earlier `phase-N` model — see the git history if you need the old workflow):

| Branch | Purpose |
|---|---|
| `main` | Production (`policywonkgame.aasifj.com`). Protected — never commit directly. The only way `main` moves is a merged `dev` → `main` pull request. |
| `dev` | Integration branch. Every change lands here first. |

```
main
 └─ dev
     ├─ feat/<slug>   (optional, for anything larger than a one-line fix)
     └─ ...
```

### Workflow

1. **Branch off `dev`** (or commit straight to `dev` for something small):
   ```sh
   git checkout dev
   git pull
   git checkout -b feat/<issue-number>-<short-slug>   # optional
   ```

2. **Build it locally.** Test with `npm run dev` (and `wrangler pages dev` for backend work — see below).

3. **Merge into `dev`.** A PR into `dev` with the Cloudflare Pages preview URL is the usual path for anything non-trivial; a direct push to `dev` is fine for a one-line fix.

4. **When `dev` is ready to ship, open one PR: `dev` → `main`.** Merging it is the release — Cloudflare Pages deploys `main` to production, so the PR diff is exactly what's already visible on the `dev` preview URL. Bump the version (`package.json` + footer) and update `CHANGELOG.md` as part of this PR.

### Hotfixes

Same flow, no special case: branch off `dev` (or commit directly to it), fix, then `dev` → `main`. There's no separate main-only hotfix path — everything goes through `dev` first, so `main` never diverges from what's actually been tested on the preview URL.

## Local development

```sh
# from policy-wonk-game/policy-wonk-game/
npm install
npm run dev              # Astro dev server
npm run build && npm run preview   # full build + preview
```

Plain `npm run dev` gets you the game (quiz, notes, search) via the Astro dev server, but **not** the backend — the API in `functions/` is Cloudflare Pages Functions, a separate runtime from Astro's dev server. For sign-in, saved history, notes-unlock, or the admin panel:

```sh
npm run dev:worker       # full build + `wrangler pages dev` — API included, against local D1
```

This needs a local D1 database migrated first — see `db:migrate:dev` in `package.json` and `wrangler.toml`'s dev block for the binding.

### Local auth bypass

`functions/api/_routes/auth.ts` exposes `/api/auth/dev-login?email=<addr>` when `ENV === "dev"`. It bypasses the magic-link flow and issues a real session cookie. Use it for local testing instead of wiring up a Brevo key. The route returns 404 in preview/production. Add `?format=json` to keep a JSON body for curl; the default is a redirect through the onboarding chain.

`SESSION_SECRET` for the JWT signer lives in `.dev.vars` (gitignored). Generate one with any random string ≥ 32 chars.

## Notes authoring

The revision notes in `src/content/notes/<module-id>/` are a blend of public-policy concepts, Aasif's own notes, and material adapted from the Takshashila GCPP readings — disclosed to readers on the notes index and in the per-note footer.

The intended pipeline is the two-stage flow in [`03-content-pipeline.md`](../03-content-pipeline.md):

```
# from policy-wonk-game/policy-wonk-game/
node scripts/ingest.js cp-22 cg-1 cp-10   # extract text from PDFs under ../<module-id>/
# read working-content/<module-id>/*.md
# author per-topic markdown under src/content/notes/<module-id>/
npm run build                              # frontmatter is validated by the content collection
```

The CP 22, CG 1, and CP 10 notes shipped in this repo were initially generated by a sub-agent that **was unable to read the source PDFs** (it hit a sandbox permission boundary) and instead authored from the question banks' `explanation` fields plus general policy knowledge. The notes read sensibly but won't reflect source-specific framings or anecdotes. Re-authoring with the proper pipeline is a worthwhile follow-up — `working-content/` regenerates from the PDFs in seconds.

Slug coverage gap to be aware of: not every `topic` slug used in `src/data/questions/<module-id>.json` has a 1:1 note file. The end-screen "Browse notes for [topic]" link in [`EndScreen.jsx`](src/components/game/EndScreen.jsx) degrades gracefully to the module index rather than 404ing when the exact note is missing — but full 1:1 coverage is still the goal. Expanding coverage to every question-bank slug is open.

## Commit conventions

- Imperative subject, ~50 char max.
- Optional body explaining *why* (the *what* is in the diff).
- Footer:
  ```
  Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>
  ```
  if Claude Code helped author the change.

Examples from the existing log:
- `Phase 5: game engine core — playable end-to-end`
- `Editorial design overhaul: type, color, layout, copy, license`
- `Remove leftover host portrait PNGs from public/`

## Cloudflare environments

Three environments:

| Environment | Branch | Database | Email |
|---|---|---|---|
| `production` | `main` | `policy-wonk-prod` | Real Brevo sends from `noreply@policywonkgame.aasifj.com` |
| `preview` | `dev` | `policy-wonk-staging` | Stubbed or routed to a single test inbox |
| local dev | — | local D1 (`policy-wonk-dev`, via `wrangler pages dev`) | Bypassed via `/api/auth/dev-login` |

Never let preview environments write to `policy-wonk-prod` or send real magic-link emails.
